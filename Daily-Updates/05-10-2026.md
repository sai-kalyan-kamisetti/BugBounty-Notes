## Bypassing a WAF 
1.  That said, techniques like JSON wrapping, double URL encoding, 
	and using lesser-known DOM events (onbeforetoggle, onpointerenter) are still worth trying. 
2. Unicode spaces, HTML comments, and even splitting SQL keywords with comments are old but sometimes still effective.
3. For XSS, try encoding characters, using uncommon tags, or building payloads client-side.
4. Double / Malformed Encoding : WAFs typically decode requests only once before pattern matching. 
	Therefore, encoding multiple times can evade detection. - bypassed imperva in 2025 jul-3.
5. Base64 + eval-less Execution.
6. Rare DOM-Events. : Other useful events:
	- onbeforematch
	- onpointerenter
	- ontoggle
	- onbeforeinstallprompt
7.  Payload Splitting & HTTP Parameter Pollution (HPP) : By splitting malicious scripts across multiple 
	parameters, WAFs treat each fragment as ‘harmless’. If the server incorrectly handles parameter merging, 
	they get reassembled in the final HTML.
	ex : ?q=<scr&q=ipt>alert(1)</script>
8. SVG·MathML Namespaces
9. MIME Sniffing + data: URI
	When servers don’t strictly specify Content-Type or miss the X-Content-Type-Options: 
	nosniff` header, browsers guess the content and render it as HTML. This allows hiding XSS in data URIs.

	<iframe src="data:text/html;base64,PHNjcmlwdD5hbGVydCgxKTwvc2NyaXB0Pg=="></iframe>
	This is a particularly common bypass point in services with file upload functionality.
